**规则提醒**
- 低血：`当前血量 ÷ 满血` 要**低于** 30% 才算。刚好等于 30%，不算低于。

## 第4步：写 `attack`（约12分钟）

这是三个函数里最长的。先看清楚它要做到什么：

初始：勇者100血，剩余冷却0，一次伤害5，攻击后进入冷却2。连续调用4次，结果必须是：

| 第几次调用 | 勇者血量 | 调用后剩余冷却 | 返回结果 |
|---:|---|---|---|
| 1 | 100 → 95 | 0 → 2 | 成功 |
| 2 | 95 → 95 | 2 → 1 | 运行中 |
| 3 | 95 → 95 | 1 → 0 | 运行中 |
| 4 | 95 → 90 | 0 → 2 | 成功 |

**“剩余冷却”的意思**：还要再等几次，才能重新造成伤害。第2、3次只是在等待，所以勇者不掉血。

你会看到三个场景。对照课件里的树，用手指出：每一步先检查了谁，在哪里停下。

**场景一：怪物只剩5点血，勇者就在旁边**
```
走过的节点： is_hp_low:success → flee:success → flee_seq:success → root:success
选择的行动： flee
```
血量低，逃跑成功，后面的“战斗分支”和“巡逻”完全没有检查。

**场景二：怪物满血，勇者距离5，范围也是5**
```
走过的节点： is_hp_low:failure → flee_seq:failure → is_hero_in_sight:success → attack:success → fight_seq:success → root:success
选择的行动： attack     勇者血量： 95
```
先检查保命分支：不低血，所以失败；然后才进入战斗分支。

**场景三：怪物满血，勇者很远**
```
走过的节点： is_hp_low:failure → flee_seq:failure → is_hero_in_sight:failure → fight_seq:failure → patrol:success → root:success
选择的行动： patrol
```
前两个分支都不适用，才去巡逻。

最后一行是 20 步模拟，应该先出现 `patrol`，然后是 `attack`，最后是 `flee`。

> 注意：冷却期间，行动名称仍然显示 `attack`，但勇者可能没有掉血。要同时看勇者血量和剩余冷却，才知道这一步有没有真的造成伤害。

## 遇到问题怎么办

| 你看到的 | 意思 | 怎么办 |
|---|---|---|
| `⏳ 请先完成 xxx` | 这个函数还没写 | 写完后，**删除 `raise NotImplementedError` 那一行** |
| `✗ ……应该是 X，你的结果是 Y` | 写了，但结果不对 | 对照第0步的规则，检查比较符号或数字 |
| `✗ 判断函数不应该修改 world` | 判断函数里写入了数据 | 找到 `world[...] = ...`，删掉它 |
| `KeyError: 'monster_hp'` | 字典里没有这个名字 | 检查拼写，大小写也要一致 |
| `IndentationError` | 缩进不对 | 函数里面的代码要往右缩进 4 个空格 |
| `ModuleNotFoundError: No module named 'tree_engine'` | 终端不在练习文件夹里 | 用 `cd` 回到有 `monster_ai.py` 的文件夹 |
| `python 不是内部或外部命令` | 命令名不对 | 改用 `python3` 或 `py` |
| `monster_ai.py` 被改乱了 | 不小心改了别的地方 | 请老师重新发一份 |
